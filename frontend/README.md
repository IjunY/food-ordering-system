# NTHU 點餐系統 前端（紫色取餐券版）

純 HTML/CSS/JS，不用建置。

## 怎麼打開

**接真後端**（建議）：照根目錄 README 啟動後端，開 http://127.0.0.1:8000 。後端會直接提供這個資料夾。

**只看畫面**（全部假資料）：

```bash
python -m http.server 5174 -d frontend
```

開 http://127.0.0.1:5174 。

開機時前端會呼叫 `GET /api/health`，有回 `{"status":"ok"}` 就用真後端，沒有就自動改用假資料（`js/mock/`）。

## 哪些接了真後端

| 功能 | 真後端模式 | 說明 |
|---|---|---|
| 註冊、登入、我的資料 | 真的 | `/api/auth/*`；註冊頁是新加的 |
| 下單、我的訂單、訂單進度 | 真的 | `/api/orders` |
| 店家接單看板（接單、完成、已取餐、拒單） | 真的 | `/api/orders/{id}/status`、`/cancel`；後端只給這個店家帳號自己店的訂單 |
| 店家「接單中／暫停接單」開關 | 真的 | `PATCH /api/vendors/{id}`；暫停後顧客下單會被後端擋下（409） |
| 餐廳列表、菜單、品項頁 | 前端資料 | 內容是 `js/mock/data.js` 的清大學餐資料；「是否接單」用後端的；下單時用「餐廳中文名＋品項中文名」換成資料庫的品項編號 |
| 等候時間 | 假資料 | 前端估的 |
| 付款 | 模擬 | 一律成功，付款紀錄只存在這台瀏覽器 |
| 店家設定、菜單管理、報表、平台管理、上傳照片 | 假資料 | |

轉接層在 `js/real/api.js`：呼叫後端，再把回傳轉成畫面用的欄位（和 `js/mock/api.js` 同一套）。

已知限制（後端還沒有對應欄位）：
- 加點選項（辣度、加蛋）與備註不會存進後端，金額以後端的菜單價格為準
- 店家帳號屬於哪家餐廳看後端的 `vendor_id`，再用店名對應到 `js/mock/data.js` 的餐廳；沒綁店家的店家帳號看不到訂單
- 取餐號碼用訂單編號（A044）；預計完成時間是前端估的
- 菜單資料（`js/mock/data.js`）和 `scripts/nthu_menu.json` 要列一樣的店名與品項名稱，改一邊要記得改另一邊（`tests/test_app.py` 會檢查）

## 使用教學（第一次登入）

`js/tour.js`。顧客和店家第一次登入（或註冊）後，會照順序帶著把功能用過一遍；平台管理員沒有教學。

- **顧客（21 步）**：選地點 → 進攤位 → 選品項、口味 → 加入購物車 → 結帳 → 選取餐時間 → 付款 → 取餐券 → 訂單進度 → 我的訂單 → 帳號（切語言、重看教學）
- **店家（14 步）**：看板上多一張練習單，從接單、完成到已取餐做一遍 → 接單開關 → 菜單管理（上架／售完、新增品項）→ 店家設定 → 營收報表
- 要使用者操作的步驟（點攤位、加入購物車、按接單…）做完會自動跳下一步；只看說明的步驟按「下一步」。離開教學那一頁時，頂列下方會出現「回到教學」
- **教學期間是練習模式**：下單、付款、訂單、接單看板一律走假資料（`api.js` 看 `store.js` 的 `inPractice()`），練習單不會送到真的店家，也不會改到真的訂單
- 看完或略過就記在這台瀏覽器（localStorage `tour_done:<身分>:<學號>`），換一台裝置會再出現一次。顧客在「帳號」頁、店家在後台頂列的「教學」可以重看
- 教學的每一步定義在 `tour.js` 的 `CUSTOMER`、`STAFF` 陣列；文字在 `i18n.js` 的 `tour.c.*`（顧客）、`tour.s.*`（店家）。改了畫面的 class 名稱要記得一起改這兩個陣列

## 假資料模式

網址參數只在假資料模式有效：`?as=customer|staff|admin` 直接登入、`?lang=en` 切英文、`?reset=1` 清掉示範資料。
假資料存在瀏覽器的 `mockdb_v3` 欄位（換成清大學餐資料時從 v2 改成 v3，舊的示範資料不會再被讀到）。

## 設計方向

照根目錄的 `DESIGN.md`（The Purple Boarding Pass）；學生端畫面對照 `mockups/student-ordering.html`。

- 紫色外殼（頂列、主要按鈕、選取中的分頁、數量鈕）＋淡紫底＋白卡；卡片不用框線，用兩層帶紫的陰影
- 訂單就是一張取餐券：紫色票頭、黃色字首的大取餐號、狀態標、撕線、四段進度。製作中是黃標，可取餐整張變綠，已取消變灰
- 黃色只用在取餐號字首與進度；綠、灰、紅只表示訂單狀態與錯誤
- 數字、代碼、價格、小標用 Archivo（壓窄）；所有文字用 Noto Sans TC。單價寫「$120」，合計與按鈕金額寫「NT$」
- 一次只顯示一種語言，右上角「中｜EN」切換
- 狀態改變時狀態標與進度條分兩格跳一下（90ms），不淡入；系統設定「減少動態效果」時全部關閉
- 店家端（桌機／平板）用同一套：紫色頂列、廚房票就是取餐券（新訂單紫、製作中黃標、可取餐綠）
- 餐廳與菜單是清大學餐的真實店家，但只列了查得到的品項；價格會變動，畫面上標「價格以現場為準」
- 只有淺色主題

設計稿有、但後端還沒有的功能沒有做：註冊後的引導（付款方式、通知）、付款方式管理、變更密碼、通知開關。

## 餐廳與菜單資料

六家清大校本部學餐櫃位：風雲樓的牛肉先生、炭烤小姐、米麵研究所，水木的利竫和食，小吃部的珈名鮮茶、蘇記牛肉麵。
2026-11-18 從 Google 地圖的公開資料整理：珈名鮮茶照 2026-03 的價目表照片列，其他店家只列評論裡寫到品項與價格的餐點。
店家簡介是我們寫的；加點選項（冰塊、甜度、飯量、餐具）、等候時間、今日單量是 Demo 設定。
`img/vendors/`、`img/items/` 是自己畫的插圖（SVG），不是實際餐點照片；Google 地圖上的照片屬於上傳的人，沒有放進 repo。
